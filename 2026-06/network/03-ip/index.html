IP 协议：寻址与路由¶

协议定位¶

IP（Internet Protocol）是互联网的网络层协议。它的核心职责只有两件事：

  1. 寻址：为每个网络接口分配一个唯一的地址（IPv4 或 IPv6）
  2. 路由：根据目标地址决定数据包该走哪条路径

IP 的设计原则是"尽力而为"——它不保证送达、不保证时序、不保证不重复。可靠性由上层（TCP）或应用层自己负责。

IP 是最小功能集协议。每个路由器只需要知道"下一跳",不需要知道整条路径，也不需要维护连接状态。

IP 数据包头部¶

一个 IP 数据包包含头部和负载。核心字段：

字段 长度 作用
Version 4 bit IPv4 (0100) 或 IPv6 (0110)
TTL 8 bit 生存跳数计数器，每经一跳减 1
Protocol 8 bit 上层协议编号（1=ICMP, 6=TCP, 17=UDP）
Source IP 32 bit 源端 IPv4 地址
Destination IP 32 bit 目标 IPv4 地址
Fragment Offset + Flags 16 bit 分片相关（见下文）
Header Checksum 16 bit 头部校验和，检测头部是否损坏

IPv6 头部简化了很多——去掉了校验和（交给链路层和上层处理）、去掉了分片相关字段（RPH 替代）、固定的 40 字节头部。

寻址：IPv4 地址结构¶

IPv4 地址 32 位（4 个字节），通常以点分十进制表示：192.168.1.1

子网掩码与 CIDR¶

IP 地址需要结合子网掩码才能知道网络部分和主机部分的分界线：

192.168.1.0/24
网络位: 192.168.1（前 24 位）
主机位: 1~254（后 8 位，0 是网络地址，255 是广播地址）

常用子网速查：

CIDR 子网掩码 可用主机数
/24 255.255.255.0 254
/16 255.255.0.0 65534
/8 255.0.0.0 16777214
/32 255.255.255.255 1（单台主机）
/30 255.255.255.252 2（P2P 链路）
/29 255.255.255.248 6（小 VPC 子网）
/28 255.255.255.240 14

三个私有地址段（RFC 1918）¶

永远不会在公网上路由，仅用于内部网络：

网段 典型用途
10.0.0.0/8 大型企业/云 VPC（10.0.0.1—10.255.255.254）
172.16.0.0/12 中型组织（172.16.0.1—172.31.255.254）
192.168.0.0/16 家庭/小型网络（192.168.0.1—192.168.255.254）

你的内网三层结构是：172.16.200.x → 192.168.0.x → 192.168.1.x。这可以看作一个大型私有网络（172.16.0.0/12）下嵌套了一个小型家庭网络（192.168.0.0/16）中又有子网关的二次 NAT。

特殊地址¶

地址 用途
127.0.0.1 loopback，指向本机
0.0.0.0 当前网络（用于广播或默认路由）
255.255.255.255 本地广播
169.254.0.0/16 DHCP 失败时的链路本地地址

路由¶

路由表¶

每个 IP 设备都有路由表。当你发送一个数据包时，操作系统查路由表决定走哪个接口、发给谁。

路由表每行包含：

目标网段    网关/下一跳      接口         优先级/度量
0.0.0.0/0   192.168.1.1     en0          1
172.16.0.0/12               en0 (直连)    0
192.168.0.0/16              en0 (直连)    0

匹配逻辑：按最长前缀匹配——有更精确的匹配（如 172.16.200.0/24）优先于更宽泛的匹配（0.0.0.0/0）。

路由决策流程¶

数据包目标: 8.163.126.172

1. 是否本机地址（127.0.0.1/localhost）？→ 否
2. 是否直连网络（在同一子网）？→ 否（本地 IP 是 172.16.200.x/？）
3. 是否有更精确的非直连路由（VPC 对等、VPN 隧道）？→ 无
4. 走默认路由 → 192.168.1.1（网关）→ en0（WiFi 接口）

最终：数据包通过 en0 发出 → 192.168.1.1 → 运营商网关 → BGP 路由协议 → 逐跳转发到 ECS

路由协议的类型¶

类型 协议 适用范围
静态路由 手动配置 家庭/小企业网络
IGP（内部网关协议） OSPF、IS-IS AS 内部
EGP（外部网关协议） BGP AS 之间（互联网的骨干路由）

TTL：控制包的生命周期¶

TTL 是 IP 包头中的一个 8 位字段（IPv4，IPv6 命名为 Hop Limit）。

设计动机： 防止路由环路导致数据包无限循环。

TTL 行为：源端设定初始值（常见 64、128、255），每经一跳减 1，减到 0 时路由器丢弃并回复 ICMP Time Exceeded。

TTL 并不是"路由可控的变量"——它只是计数器。网络无法根据 TCP 连接的状态或用户的带宽来动态调整 TTL。它唯一的作用是封死无限循环的可能。

分片与路径 MTU 发现¶

IP 分片¶

当 IP 数据包大小超过下一跳链路能承载的最大传输单元（MTU）时，路由器或源端可以将数据包拆成多个分片发送。

  • 以太网标准 MTU：1500 字节
  • PPPoE（常见于宽带拨号）：1492 字节（少 8 字节 PPPoE 头部）

分片在目标端重新组装——中间路由器不对分片做任何处理（路由本身不需要重组）。分片只在目标端进行重组。

不要分片（DF）标志¶

IP 头部有一个 DF（Don't Fragment）标志。设置后，路由器遇到超 MTU 的包不会分片，而是丢弃并回复 ICMP Fragmentation Needed（Type 3 Code 4）。

这就是 PMTUD（Path MTU Discovery）的核心机制： 源端发送 DF 标志的探测包，如果收到 ICMP Fragmentation Needed，就知道路径上的 MTU 更小，然后减小探测包大小继续发，最终找到整条路径上的最小 MTU。

实际中常见的问题¶

PPPoE 拨号的 MTU 默认是 1492，但很多应用和 TCP 连接默认用 1500。如果路由器不处理 ICMP Fragmentation Needed 回复（如防火墙拦截了 ICMP），发送方就无法得知路径 MTU 变小，表现为"部分站点打不开"或"大文件传输卡死"。

解决方法是手动将网卡或路由器的 MTU 改为 1492 或更低（常见值：1450）。

操作速查¶

# 本机网络接口
ifconfig en0                 # 查看 WiFi 接口 IP、MAC、MTU、状态
ifconfig en0 | grep inet     # 只取 IPv4 地址

# 路由表
netstat -rn                  # 内核路由表
route -n get default         # 查看当前默认网关
route -n get 8.163.126.172   # 查看具体目标走哪个接口/网关

# 主动路由追踪
traceroute -n 8.163.126.172  # 同上，来自 ICMP 篇

# 手动添加/删除路由（需 root）
sudo route add -net 10.0.0.0/24 192.168.1.100
sudo route delete -net 10.0.0.0/24

# 子网计算
ifconfig en0 | grep netmask  # 查看本机子网掩码

思考题¶

  1. 如果路由表中的默认路由（0.0.0.0/0）也被删除了，会发生什么？
  2. 为什么 MTU 不匹配且在防火墙屏蔽了 ICMP 的情况下，会导致特定连接挂死？
  3. 本机的私有 IP（如 172.16.200.x）如何被映射为公网 IP 发送到互联网上的目标？（NAT 的概念，参考下一章或自行探索）
